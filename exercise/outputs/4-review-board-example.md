# ตัวอย่างบันทึกประชุมจำลอง: ทบทวน ADR-0002

> **สถานะ: ตัวอย่างจำลองที่ AI แต่งตามคำขอ** รายชื่อมาจากผู้ใช้ แต่บทบาท ผู้ยกประเด็น เหตุผล และข้อสรุปรายประเด็นด้านล่างเป็นสถานการณ์สมมติ ไม่ใช่หลักฐานว่าบุคคลเหล่านี้ได้พูดหรือลงมติจริง ให้ปรับตามเหตุการณ์จริงก่อนนำไปใช้เป็นบันทึกประชุม

- **วันที่จัดทำตัวอย่าง:** 2026-10-27
- **วันที่ประชุมจริง:** ยังไม่ได้ระบุ
- **ADR สำหรับตัวอย่าง:** [ADR-0002](../../docs/adr/0002-use-rabbitmq-for-post-order-actions.md)
- **ผลรีวิวที่ใช้ประกอบ:** [3-review.md](3-review.md)
- **รายชื่อที่ผู้ใช้ให้:** ชวภณ สุวรรณะ; ณัฐเมธีโพเลิศสวัส

| ณัฐเมธีโพเลิศสวัส | ผู้ทบทวนที่ตั้งคำถามด้านธุรกิจและการปฏิบัติการ |

## สรุปการอภิปรายในสถานการณ์จำลอง

ชวภณเสนอให้ใช้ PostgreSQL transactional outbox ร่วมกับ RabbitMQ เพื่อให้งานอีเมล แต้ม และ analytics แยกจาก request ของ checkout และเพิ่ม consumer สำหรับ action ปีหน้าได้ การให้แต้มใช้ ledger กับ unique key และ transaction เดียว ไม่อ้างว่า broker ส่งข้อความ exactly once

ณัฐเมธีตั้งคำถามว่าคิวจะทำให้แต้มทันหนึ่งนาทีได้หรือไม่ หาก loyalty ใช้งานไม่ได้ ชวภณอธิบายว่าคิวช่วยเก็บงาน แต่ outage ที่นานเกินกำหนดยังทำให้เกิด SLA breach ได้ จึงต้องให้ธุรกิจตัดสินนิยามเวลาและข้อยกเว้น โดยไม่เปลี่ยนข้อกำหนดเอง

ณัฐเมธีถามต่อเรื่อง payment สำเร็จแล้ว process ล่มก่อน order/outbox commit และภาระดูแล broker กับ stores ข้อเสนอคือบันทึก intent/operation ID ตรวจผลก่อน retry และกำหนดเจ้าของ reconciliation พร้อมเปรียบเทียบต้นทุนกับ PostgreSQL job store ที่ไม่มี broker

## การประเมิน AI — ตัวอย่างความเห็นจำลอง

- **ข้อค้นพบที่ดีที่สุดในตัวอย่าง:** ความขัดแย้งระหว่างการรับ order ต่อกับแต้มภายในหนึ่งนาที เพราะทำให้แยกความทนทานของข้อมูลออกจากความทันเวลาได้ชัดเจน ไม่ได้ยืนยันว่ามนุษย์มองข้ามเรื่องนี้จริง
- **ข้อค้นพบที่ยังอ่อนในตัวอย่าง:** ข้อเสนอให้ทีมประเมินภาระปฏิบัติการยังไม่สามารถบอกต้นทุนจริงได้ เพราะไม่มีข้อมูล on-call, เวลา backup/restore หรือผลทดสอบ ไม่ได้หมายความว่ากลุ่มได้ตัดสินเช่นนี้จริง

## Decision Record — ตัวอย่างจำลอง

- **แนวทางในตัวอย่าง:** คง Option 3 — PostgreSQL transactional outbox + RabbitMQ
- **เหตุผลตัวอย่าง:** รองรับ action เพิ่มและแยก downstream ออกจาก checkout โดยยอมรับภาระปฏิบัติการเพิ่ม
- **ประเด็นที่เปิดไว้:** SLA แต้มเมื่อ outage ยาว, API ภายนอก, ผู้รับผิดชอบ reconciliation และความจุจริง
- **ผู้ลงมติและวันที่จริง:** ยังไม่ระบุ
- **ผลทดสอบ:** ยังไม่ได้รัน
